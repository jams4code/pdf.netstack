## How compression works

<Steps>

1. **Read.** The file is parsed with limits on nesting, stream sizes and image sizes. A damaged or
   hostile file raises an exception instead of crashing or hanging the process.

2. **Rewrite.** Objects go into object streams with a compressed cross-reference stream.
   Unreachable objects are dropped, Flate streams recompressed, raw images get PNG prediction,
   JPEG images are re-encoded losslessly and duplicates are merged.

3. **Prove.** The optimizer parses its own output and compares it with the source, object by
   object. Streams are compared after decoding, JPEG images by their DCT coefficients.

4. **Return.** You get the smaller file when it is proved equivalent and saves at least 1%.
   Otherwise you get your original bytes, and `result.Reason` tells you why.

</Steps>

Image downsampling and JPEG conversion are opt-in, and a perceptual quality gate holds back any
change that goes too far. [Compress PDF](/guides/compress-pdf/)

## Performance

### Public corpus, measured on every release

CI downloads 77 openly licensed and public domain PDFs (NIST and NASA publications, arXiv papers,
government gazettes, test files) and optimizes each one with three profiles. Results for 1.1.0 on
a 4 core Linux runner:

| Profile | Saved | Failures | Rendering |
|---|---:|---:|---|
| Lossless, the default | 12.1% | 0 | Checked pages identical in PDFium |
| Balanced preset | 23.4% | 0 | Image changes gated at SSIM 0.95 |
| Lossy profile | 29.5% | 0 | Image changes gated at SSIM 0.95 |

Signed and encrypted files are kept as they are, by design. The lossless run took 44 seconds for
196.6 MiB, proof included. The full report is attached to the
[1.1.0 release](https://github.com/jams4code/pdf.netstack/releases/tag/v1.1.0), and you can run
the same benchmark yourself.

### Real world corpus
