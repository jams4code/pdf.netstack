Notes on web fonts and print

The first thing to know about a web font is that the browser never sees the file you designed. It sees a compressed copy, and the compression is the part of the format that changed the most between the first and the second version of the standard. The older format wrapped each table on its own. The newer one puts every table into a single stream, which lets the compressor find the same patterns across the whole font.

For a document converter this matters in a simple way: if the style sheet of a page says that the heading uses a particular family, and that family is only available as a compressed web font, then the converter must be able to read it, or the heading will be drawn in a fallback face that the author did not choose.

What the converter does

  • It reads the style sheet and finds every rule that declares a font face.
  • It loads the first source that it can read, and skips the ones it cannot.
  • It rebuilds the font tables, checks them, and embeds only the glyphs that the page uses.

Because fonts come from pages that anyone can write, the reader treats every number in the file as a claim to be checked. A length that runs past the end of the data is an error. A count that would need more bytes than the stream holds is an error. A table that decompresses to more than the limit is an error. None of these errors should take down the process that is reading the page.

Why the details matter

The International Organization for Standardization publishes the Open Font Format, and the World Wide Web Consortium publishes the web font formats. They describe the same tables in slightly different words. When the two descriptions disagree, the safest choice is the one that keeps the output valid for every reader, including the ones that were written a long time ago.
